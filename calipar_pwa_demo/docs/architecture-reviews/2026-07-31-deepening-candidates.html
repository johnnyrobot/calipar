AGENTS.md states this as a hard rule — “Repository mutations and corresponding activity records must commit in one transaction.” Today it is enforced by convention across 5 call sites, not by an interface. A sixth mutator can silently omit the activity or the publish.

The same gap at the call sites

· expectedRevision passed at only 3 of 9 mutation sites.
· planning/page.tsx:65 passes it with no handler for the CONFLICT it can raise.
· resources/page.tsx never passes it on any path.
· chat/page.tsx:109 writes outside its own try — a failure is an unhandled rejection with no UI.
· the catch-and-stringify idiom is written 12×, while workspace-provider.tsx:26-30 already has it extracted as errorMessage() — unexported.

Problem

The atomicity-and-notify invariant lives in 5 implementations instead of 1 interface.

Solution

Mutators declare what changed; a commit module owns transaction, activity, and publish.

  • · locality: invariant in one module
  • · new mutators can't forget the activity
  • · one test proves atomicity for all
  • · interface shrinks; implementation absorbs it

This module is already deep, and should stay that way. handleRequest over 1350 lines is a small interface with a large implementation — correct. The proposal is an internal seam, private to the implementation and used by its own tests. Nothing new is exported.

What the missing seam costs today

· every authenticated test round-trips /api/ai/session with a faked Turnstile just to mint a cookie.
· that offsets the fetch stub, so assertions index mock.calls[1] and count toHaveBeenCalledTimes(2) to skip it.
· the four-arm task switch is restated 4× — schema, prompt, validator, token limit.
· the error envelope from AIErrorPayload is hand-rebuilt 3× (:82, :816, :1278).

Problem

The product's central safety claim has no interface — it is six checks reachable only through HTTP.

Solution

One internal module owns the routing policy; the transport calls it.

  • · policy assertions need no fetch stub
  • · locality: one module to audit
  • · external interface unchanged
  • · leverage: 2 transports, 1 policy
